## 0. 愿景与定位

把 027-file-manager 从「能用的双栏浏览器」升格为 **桌面默认文件中枢**：

- **最强**：融合 Windows Explorer（易用性/面包屑）、macOS Finder（列视图
  空间感/Quick Look 预览）、Total Commander（键盘优先/批量操作）、
  Everything（即时搜索）、Directory Opus（可配置/收藏与虚拟位置）各自
  的差异化长处，形成统一交互语言。
- **最快**：在 AutoOS 框架（.at + VM/vue 双轨）现实能力内做到响应速度
  的跨越式提高——交互零重读盘、渐进渲染不截断、原生排序、后台搜索
  不阻塞 UI、缩略图主线程零解码。

「最快」的可验证口径见 §3 性能需求；「最强」的功能口径见 §2 功能矩阵。
明确不做的（列视图 Miller Columns、双文件面板、标签页、全盘 MFT 索引、
插件系统、脚本化）见 §5 范围外。

## 1. 现状基线与核心痛点

v0.6 已有（SPEC.md 全量在册）：快捷访问/盘符侧栏、面包屑（深路径坍缩）、
历史栈、地址栏编辑跳转、列表/网格视图、四列排序、隐藏项过滤、目录内
搜索、网格缩略图（VM 媒体管线）、新建/重命名/删除（空目录）/复制/剪切/
粘贴（单条目）、右键菜单、Enter 打开 + 桌面 open_with 互操作、双主题、
storage 持久化、vue/VM 双轨降级。

四大性能债（本次重构的靶心）：

| # | 债 | 现状证据 |
|---|----|---------|
| D1 | **交互即全量重读盘**：排序换列、隐藏切换、搜索每敲一个字符，全部汇聚 `NavTo` 重跑 `fs.read_dir` + 逐条目三件套 metadata syscall | app.at `SortByName/SortBySize/SortByDate/SortByType/ToggleHidden/SetSearch` 均尾调 `.NavTo(.current_path)` |
| D2 | **500 条硬截断**：大目录（node_modules、缓存目录）不可用 | app.at `kept >= 500` 截断 + 状态栏「已截断」 |
| D3 | **解释器 O(n²) 选择排序**：500 条 = 12.5 万次解释比较；扩容到万级不可行 | fs_util.at `sort_files`（025 sys_store 同款 marks 选择排序） |
| D4 | **逐条目同步 metadata 三件套**：每条 3 次 native 调用，万级目录 = 3 万次 syscall 同步阻塞 handler | app.at 物化循环 `file.is_dir/file.size/fs.mtime` |

交互面短板：仅 Enter 一个键盘动作、无多选（一切操作单条目）、非空目录
不能删、无预览面板、搜索只过滤当前目录、粘贴遇同名只会报错。

## 3. 性能需求（量化验收）

**PLAN-001 rev 2 实测口径修正（2026-10-04）**：验收一律**应用内计时**
（`last_snapshot_ms/last_derive_ms`）——MCP fixture 墙钟在大状态上是
~3s 级仪器噪声，不可作为门；P-3 万级受 VM 记录对象规模墙约束
（3k-10k 离散故障，框架侧债），落地为 SNAP_CAP=8000 分层 + 诚实标注。
实测基线：2000-6000 项快照+派生应用内 **0ms**（perf_check ALL PASS）。

测量环境：dev 机 VM 轨（`auto run -r vm`），desktop_mcp 套件 +
tests/mkbig.py + tests/perf_check.py（应用内计时门）。

| # | 指标 | 目标 | 手段 |
|---|------|------|------|
| P-1 | 目录切换首屏（含元数据） | ≤500 项 ≤150ms；≤5000 项 ≤400ms | 单次读盘 + 原生物化 |
| P-2 | 交互延迟（排序换列/隐藏切换/过滤击键） | **零 fs.read_dir 调用**，一拍内派生完成（5000 项 ≤80ms） | D1 三层分离（设计 §2） |
| P-3 | 大目录 | 10000 项无截断可浏览；渐进渲染不冻结 UI | render_cap 扩窗（设计 §4） |
| P-4 | 排序 | 10000 项 ≤100ms | 原生 sort_by + 8 具名比较器（设计 §5） |
| P-5 | 过滤 | 10000 项 contains ≤100ms/击键 | 预小写 key + 单遍扫描 |
| P-6 | 缩略图 | 主线程零解码（既有管线维持）；列表模式 cap 120 | 已有 image.thumb 管线 |
| P-7 | 递归搜索 | 后台协程不阻塞 UI；结果流式呈现；取消即时（≤1 拍） | 世代计数取消（设计 §8） |
| P-8 | 启动 | Init 轻量纪律维持（重 FS 活在首个稳定 Tick） | 既有纪律不动 |

回归门：既有 desktop_mcp T1-T14 行为用例全绿（导航/隐藏/搜索/新建/
重命名/删除/排序/持久化语义不回退）。

## 4. 非功能需求

- **双轨一致**：VM 轨为事实轨全功能；vue 轨维持调试轨定位——读盘走
  既有 HTTP 后端（fs_list 等），预览文本 api.at 补端点；写操作/缩略图/
  递归搜索保持 VM 轨专属 + 明确降级文案（既有守卫口径扩展）。
- **主题**：全语义 token + dark_mode 回写链维持；新 UI 面不得引入硬编码色。
- **持久化**：新增状态（收藏夹、预览面板开关、渐进渲染档位）storage
  落盘，键名 `fileman.*` 命名空间。
- **测试**：desktop_mcp.py 注入式驱动扩展新用例族；性能断言容差门
  （CI 机器波动 ±50%）；破坏性操作只对 tests/testdata 副本。
- **安全**：递归删除必须双门（确认模态 + 目录项数展示）；路径恒经
  canonical；搜索结果路径只读消费。
